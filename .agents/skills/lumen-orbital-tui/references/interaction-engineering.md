# 实现适配

这里是平台经验，不是风格定义。只应用与目标技术栈有关的部分。

## 共同判断

主题令牌对应语义角色，而不是绑定某个组件。页面重排后仍应能看出同一套表面、排版和强调关系。悬停、焦点、选中、按下不是同一种状态，可以共用色系，但不能失去区分。

验证时看实际目标表面。截图评审外观，完整操作流程评审可用性；两者不能相互代替。

## TUI 实际陷阱

- **破碎背景**：子样式的 ANSI reset 返回终端默认底色，而非所属面板。背景组合需要恢复父级样式，不能只给文字片段着色。
- **点击偏移**：Bubblezone v1 的 go-runewidth 与 x/ansi 可能在 CJK locale 下对 ambiguous 字符算出不同宽度。统一策略，不硬补按钮坐标。若目标终端确为单格 ambiguous 字符，可在初始化时统一 go-runewidth 的 EastAsianWidth 设置；中文表意文字仍双格。
- **编辑错位**：组件尺寸在状态更新时管理，不在 View 的临时副本中另改一套宽度。
- **动画复活**：tick 带 generation，关闭/重启后拒绝旧帧，避免多条调度链。
- **日志误判**：纯文本不能验证背景与渐变。颜色动画可能只变 RGB、不变字符；应检查真实帧。

## Web / 桌面迁移

不要把终端的字符限制一起移植。保留语义令牌和层级关系，利用原生文字排版、布局、焦点与图形能力。边框、阴影、模糊、材质可按平台使用，强度服从整体低噪声方向。

动效方案和帧率由平台、内容与性能决定，不受点阵案例的 12 FPS 限制。少量视觉亮点可以更丰富，常驻工具区域保持稳定。
