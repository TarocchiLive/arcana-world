# WebSocket 弹幕广播

## 启用与连接

在 TUI「设置」中设置「WebSocket 监听地址」，再开启「WebSocket 广播」。默认关闭，默认地址为 `127.0.0.1:8080`。地址使用 `主机:端口`，例如 `127.0.0.1:8080` 或 `[::1]:8080`，不包含 `ws://` 或路径，端口范围为 1–65535。

地址和开关保存到 `config.json` 的 `websocket_addr`、`websocket_enabled`。广播运行时修改地址立即切换监听，原连接断开，客户端需连接新地址；绑定或保存失败时保留原服务。广播关闭时修改地址不会启动服务。

命令行 `--websocket-addr 127.0.0.1:8080` 仅本次运行覆盖地址并启用广播；此时界面不能修改地址。客户端连接 `ws://127.0.0.1:8080/ws`。监听服务不提供 TLS。

需启用弹幕接收，并监听直播间。广播只转发实时弹幕和礼物，不重放历史，不受 TUI 的显示数量限制影响。

## 消息格式

每个 WebSocket 文本帧包含一个 JSON 对象：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `room_id` | 整数 | 事件所属直播间 ID |
| `event` | 对象 | B 站原始事件对象，保留原始字段，不转换为界面文本 |

仅转发 `event.cmd` 主命令为 `DANMU_MSG` 或 `SEND_GIFT` 的事件。主命令按第一个冒号分割，例如 `DANMU_MSG:4:0:2:2:2:0` 也会转发，`cmd` 原值不变。其他事件和无效 JSON 不转发。

以下为精简的结构示例，不代表上游完整字段：

```json
{"room_id":12345,"event":{"cmd":"DANMU_MSG","info":[[],"你好",[67890,"用户",0]]}}
```

```json
{"room_id":12345,"event":{"cmd":"SEND_GIFT","data":{"uid":67890,"uname":"用户","giftName":"小心心","num":1}}}
```

弹幕正文通常位于 `event.info[1]`，发送者信息通常位于 `event.info[2]`；礼物信息位于 `event.data`。这些字段来自上游协议，可能变化或缺省，客户端应检查类型和字段存在性，并忽略不认识的字段。协议没有额外的版本号、序号或确认消息。

## 只读与断线

客户端无需发送订阅消息。服务仅广播，不接受发送弹幕或控制指令；客户端不应发送应用数据帧。每个客户端最多排队 64 条消息，队列满或单次写入超过 5 秒时断开。客户端自行重连，断线期间事件不会补发。

## 安全

服务没有认证。默认只绑定本机；绑定 `0.0.0.0`、`[::]` 或局域网地址会向能访问该端口的设备暴露直播间事件，请配合可信网络和防火墙使用，不要直接暴露到公网。

浏览器 WebSocket 请求的 Origin 主机须与连接目标主机匹配，跨站页面不能直接订阅。没有 Origin 的非浏览器客户端不受此检查限制；来源检查不是认证。
